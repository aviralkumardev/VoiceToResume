# Frontend: Build & Project Config

## Purpose
Next.js/TypeScript/tooling configuration — not application logic, but
required context for anything touching how the app builds, lints, or
resolves modules.

## Key files
- `frontend/next.config.ts` — Next.js config (currently near-empty
  default).
- `frontend/tsconfig.json` — TypeScript compiler options + path aliases
  (`@/*` → `src/*`, used throughout every import in this codebase).
- `frontend/package.json` — scripts (`dev`, `build`, `start`, `lint`) and
  dependencies.
- `frontend/eslint.config.mjs` — flat ESLint config.
- `frontend/.env` — `NEXT_PUBLIC_API_BASE_URL` and any other public env
  vars (see [frontend/api-client.md](api-client.md)).
- `frontend/AGENTS.md` (aliased from `frontend/CLAUDE.md` via `@AGENTS.md`)
  — auto-generated-by-`next dev` notice about this Next.js version
  potentially differing from training data; re-added by `next dev` on
  every run, so don't fight it in diffs.

## Public surface
- npm scripts: `dev` (`next dev`), `build` (`next build`), `start`
  (`next start`), `lint` (`eslint`).
- Key dependencies: `next@16.3.4`, `react@19.2.8`, `@daily-co/daily-js` +
  `@daily-co/daily-react` (Daily WebRTC + React bindings), Tailwind v4
  (`tailwindcss` + `@tailwindcss/postcss`).

## Data flow & dependencies
- `@/*` path alias (from `tsconfig.json`) is used in essentially every
  frontend import (`@/components/...`, `@/lib/...`) — any restructuring of
  `src/` must keep this alias resolvable.
- `frontend/CLAUDE.md` is just `@AGENTS.md` — a Next.js-generated
  redirect. The actual content future sessions should read is in this
  `.claude/` map (project root `CLAUDE.md` + these domain files), not in
  `frontend/CLAUDE.md`/`AGENTS.md`, which cover Next.js-version-specific
  API-drift warnings, not this app's own architecture.

## Conventions & gotchas
- `frontend/AGENTS.md`'s content is regenerated by `next dev` itself —
  don't hand-edit it expecting the change to stick; if it shows up as an
  uncommitted diff, that's normal churn from running the dev server, not a
  bug.
- No `tailwind.config.js` — this is Tailwind v4's CSS-first config style;
  if you're used to v3, don't go looking for it, check `globals.css`
  ([frontend/styling-globals.md](styling-globals.md)) instead.
